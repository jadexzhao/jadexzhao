BM25 notes search

Python 3, standard library only for search. Two files do the ranking: bm25.py and search.py.

Overview

I wanted to search a folder of markdown notes by keyword without an API key or a vector database. The programme walks a directory, tokenises each .md file, scores documents with Okapi BM25, and prints a short snippet from the best-matching lines.

A run I actually executed

From the repository root, 30 October 2026, against the project folder itself:

How ranking works

Tokens are lowercase [a-z0-9]+ runs. For each query term that appears in a document, the score adds inverse document frequency times a saturated term-frequency term. Longer documents are slightly down-weighted. Defaults in BM25Index are k1 = 1.5 and b = 0.75.

In plain language: a word that is rare across the folder but common in one note helps that note rise. Repeating the word helps less and less. A long note does not automatically win.

My role

I wrote the ranker, the CLI, a small fixture corpus, and the tests. Optional local-model asking is a separate script. It never downloads a model by itself.

Technical decisions

  • No third-party packages on the search path, so python3 search.py still runs on a laptop with nothing extra installed.
  • The index is rebuilt on every run. Fine for tens of notes; not a persistent search service.
  • Snippets pick the line with the most query-token overlap, then two lines of context. That is a display helper, not part of the BM25 score.
  • score() from bm25.py, colour added ahead of time. The highlighter does not load in the browser. 
    def score(self, query_tokens: list[str]) -> list[tuple[float, Document]]:
        if not query_tokens or not self.documents:
            return []

        scores: list[tuple[float, Document]] = []
        for idx, doc in enumerate(self.documents):
            total = 0.0
            tf_doc = self.tf[idx]
            for term in query_tokens:
                freq = tf_doc.get(term, 0)
                if freq == 0:
                    continue
                idf = self._idf(term)
                denom = freq + self.k1 * (1 - self.b + self.b * doc.length / self.avg_dl)
                total += idf * (freq * (self.k1 + 1)) / denom
            if total > 0:
                scores.append((total, doc))

        scores.sort(key=lambda item: item[0], reverse=True)
        return scores

What a reviewer can inspect

python3 -m unittest discover -s tests -v in bm25-notes-search/ ... 15 tests, including ranking, passage splits, and a mocked local-model failure. Live model generation was not run here. No model was downloaded.

Limitations

  • No stemming, so tokeniz does not match tokenize.
  • No embeddings, synonyms, or phrase queries.
  • File-level search has no web UI and no saved index. The optional local-model path is not a public endpoint.
