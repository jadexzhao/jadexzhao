# Portfolio template research · student SWE (2024 to 2026)

Synthesis for `briefcase/template/` (jadexzhao technical proof door). Not MAP classroom tone.

## Upgrade principles (named)

1. **Curated depth** (Pattern A) ... Three to five finished stories beat a long skills cloud or ten half-done repos (UCA career guide, 8seneca-style hiring guides, interview prep sites).
2. **Hero + proof rail** (Pattern B) ... One-screen identity, graduation or programme facts, and CV / GitHub / email without hunting (archived briefcase proof-band; recruiter scan literature).
3. **Case-study shaped work** (Pattern C) ... Context before the repo: problem, role, stack, demo, lessons. ICS 314 explicitly warns against linking GitHub alone without your narrative.
4. **Scan-friendly IA** (Pattern D) ... Skip link, sticky nav, on-page outline, grouped skills, static HTML for speed on GitHub Pages.
5. **Front-loaded hire signal** (Pattern E) ... Target role and primary stack in the first viewport; recruiters often decide in roughly 6 to 30 seconds whether to read further (Ladders eye-tracking on CVs; portfolio guides extrapolate similar behaviour).
6. **Evidence-tier outcomes** (Pattern F) ... Separate defended facts, hypothetical metrics you would track, and lessons. Do not invent KPIs; transparency beats fake precision (UX career threads; femkedesign-style case study honesty).
7. **Anchor spotlight** (Pattern G) ... One flagship project gets visual priority and a deep write-up page; supporting cards stay shorter (interviewchamp / depth-over-breadth side-project guidance).
8. **Accessible static craft** (Pattern H) ... Semantic landmarks, visible focus, ~4.5:1 body contrast, `prefers-reduced-motion`, minimal dependencies, Lighthouse-friendly static assets (W3C C39; student portfolio a11y statements).

## Recruiter lens (30 to 60 seconds)

- Name, target role, and degree timeline visible immediately.
- One live demo or shipped artefact above the fold or linked from the first project card.
- Contact and GitHub in one click; mobile layout must not hide CTAs.
- Skills only where tied to projects or CV bullets.

## HCI / research student structural ideas (optional)

- Lead with research question and methods, not tool list (HCI portfolio norms; CMU MHCI examples).
- Separate **ships** (code) from **inquiry** (essays on another door if you use four-doors).
- Public-safe overview pages; no clinical or IRB framing on the portfolio door.
