Code as dialogue

Whether I am supporting Hudson & Holland Scholars Program (HHSP) scholars as a Program Assistant or walking a Serve IT partner through a form flow, I talk about programmes the same way: what did you expect, what printed, what would you change?

Human + AI Co-Create on campus taught me to name what a tool did in the assignment (clarify wording vs draft code) and still own the explanation in my own words. No product names on this page ... just the habit of question, attempt, revise.

Scratch in my head

Before Python clicks, I still narrate the green-flag story: set a variable, say something, change a counter, or the loop never ends. My public INFO-I211 notes keep that pairing on purpose.

num = 3  # whole number in a box
# Scratch: set [num v] to (3)
print(f"{num} squared is {num ** 2}")
# Scratch: say (join [num] [ squared is ] [num ** 2])

pattern from week 1 Code Conversation ... predict the printout, then change one value and re-trace.

Question → try → revise

Not a chat log. The shape I reuse in office hours and clinic intake:

  1. Question: "What should happen when the name box is empty?"

    Try: run with name = "" and watch the branch.

  2. Question: "Why did Python sulk about a hyphen in the variable name?"

    Try: rename to first_name ... Scratch would not let you glue a minus sign in a label either.

  3. Revise: "Okay, so empty string is a costume with nothing in it. Next week we guard the divide-by-zero path the same way."

Guessing games and full assignment submits stay off the public site. The week-by-week watch-it / try-it gallery lives in the archived Code conversions hub (Drive clips + snippets).
